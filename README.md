# 기출 변형문제 열람 웹서비스 — 화면 프로토타입

토목구조기술사 기출문제를 변형한 문항과 그 해설을 회차·교시별로 열람하는 웹서비스의 화면 프로토타입이다.
동작하는 서비스가 아니라 **화면 구성과 사용자 흐름을 확인하기 위한 정적 산출물**이다.

- 근거 문서
  - 「기출 변형문제 열람 웹서비스 업무 플로우 및 요구사항 정의서」 v0.1 (2026-08-19, 고상우)
  - 「토목기술사 문제풀이 서비스 기획 초안」 v3 (2026-08-22, 최승호)
- 콘텐츠 — 제139회 3교시 실제 데이터 (문항 6건 · 도면 11건, 검수 완료본)

---

## 1. 실행

정적 파일이므로 별도 빌드나 서버가 필요 없다.

```bash
# 로컬에서 열기
open index.html

# 또는 로컬 서버로
python3 -m http.server 8000
```

### GitHub Pages 배포

1. 이 디렉터리를 리포지터리 루트에 올린다.
2. Settings → Pages → Source를 `main` 브랜치 `/ (root)`로 지정한다.
3. `https://<계정>.github.io/<리포명>/` 에서 열린다.

`.nojekyll` 파일이 포함되어 있다. Jekyll 빌드를 건너뛰어 파일명이 그대로 유지된다.

## 2. 구성

```
.
├── index.html                  화면 3종 전체 (단일 파일)
├── data/
│   ├── 139-3.public.json       공개 필드만 담은 콘텐츠 데이터
│   └── categories.json         과목 분류 매핑 (원본 데이터 외부)
├── drawings/
│   ├── svg/                    도면 원본 11건 — 화면에서 사용
│   └── png/                    도면 원본 11건 — 대체용
├── tools/
│   └── build.py                데이터 → index.html 생성 스크립트
└── README.md
```

`index.html`은 `tools/build.py`가 원본 데이터에서 생성한 결과물이다. 직접 편집하지 말고 스크립트를 다시 돌린다.

## 3. 사용자 기준 업무 플로우

```
1. 웹 접속                 로그인 없이 진입
        ↓
2. 회차 선택               드롭다운
        ↓
3. 교시 선택               드롭다운 (1~4교시)
        ↓
4. 문항 목록 표시          해당 교시의 변형문제 전체
                           · 답은 보이지 않는 상태
                           · 각 문항에 오마주 출처 표기
        ↓
5. 해설보기 클릭           문항별 개별 동작
        ↓
6. 해설 표시               모범답안 + 도면
```

### 화면 구성

기획 초안 v3의 화면 ID를 따른다. 이번 범위는 SCR-001~004이다.

| 화면 ID | 화면명 | 구성 요소 | 구현 |
|---|---|---|---|
| SCR-001 | 메인 (이용 방식 선택) | 서비스 개요, 회차별·과목별·랜덤 진입 | ○ |
| SCR-002 | 회차 선택 | 회차 드롭다운, 교시 드롭다운 | ○ |
| SCR-003 | 과목 선택 | 과목 목록, 과목별 문항 수 | ○ |
| SCR-004 | 문제 목록/상세 (공용) | 문항 번호, 오마주 출처 배지, 과목·회차·유형·난이도, 문제 본문, 문제 도면, 해설보기 | ○ |
| SCR-005 | 신고 입력 (모달) | — | ✗ 범위 밖 |
| SCR-006 | 추가풀이 등록 | — | ✗ 범위 밖 |
| SCR-007 | 추가풀이 현황 조회 | — | ✗ 범위 밖 |
| SCR-A00 | 관리자 로그인 (숨김 URL) | — | ✗ 인증 미구현 |
| SCR-A01 | 관리자 대시보드 | 처리 대기 건수 3종, 각 화면 진입 | ○ |
| SCR-A02 | 신고 처리 | 상태 탭, 신고 목록, 검토 시작·반영·기각 | ○ |
| SCR-A03 | 추가풀이 검토 | 상태 탭, 등록건 목록, 게시·반려(사유 선택 입력) | ○ |
| SCR-A04 | 문제·풀이 게시 | 문항 목록, 작성중 ↔ 게시됨 전환 | ○ |

SCR-004는 **문제 카드 컴포넌트 1개 + 목록 컨테이너 3종** 구조다. 카드 마크업은 한 번만 생성하고 진입 경로(회차별/과목별/랜덤)에 따라 필터와 정렬만 바꾼다. 문항 목록과 해설 펼침은 같은 화면의 두 상태다.

### 관리자 화면

메인 하단 "관리자" 버튼으로 진입한다. **인증이 없다.** 정적 파일이라 인증을 붙일 수 없고, 이번 범위에서는 화면 확인이 목적이므로 버튼으로 바로 들어가게 두었다. SCR-A00(로그인)은 만들지 않았다.

상태 전이는 기획 초안 6절의 상태 다이어그램을 그대로 따른다.

| 화면 | 전이 |
|---|---|
| SCR-A02 신고 | 접수됨 → 검토중 → 반영 / 기각 |
| SCR-A03 추가풀이 | 검토대기 → 검토중 → 게시됨 / 반려됨 |
| SCR-A04 문제·풀이 | 작성중 ↔ 게시됨 |

신고·추가풀이는 원본 데이터에 없으므로 **예시 데이터**를 `tools/template.html`의 `REPORTS`·`EXTRAS` 배열에 두었다. SCR-A04의 문항 목록만 실제 데이터이며, 모범답안이 있는 3건은 게시됨, 없는 3건은 작성중으로 초기 상태를 잡았다. 모든 상태 변경은 화면 안에서만 유지되고 새로고침하면 사라진다.

### 진입 경로별 동작

| 경로 | 목록 구성 | 비고 |
|---|---|---|
| 회차별 | 회차·교시로 필터, 문항 번호 순 | 카드의 회차 칩은 중복이라 숨김 |
| 과목별 | 과목으로 필터, 문항 번호 순 | 카드에 회차 칩 표시 |
| 랜덤 연습 | 전체, 무작위 순서 | 상단 "다시 섞기" |

### 분기·예외 처리

| 상황 | 처리 | 현재 데이터에서 |
|---|---|---|
| 콘텐츠가 없는 회차·교시 | 드롭다운에서 선택 불가 | 1·2·4교시 비활성 |
| 해설이 아직 없는 문항 | 해설보기 버튼 비활성 | 문항 4·5·6 (계산형 3건) |
| 도면이 없는 문항 | 본문만 표시, 빈 영역 없음 | 문항 3은 문제 도면 없음 |
| 문항이 없는 과목 | 과목 목록에 미노출 | 강구조 등 |

## 4. 필수 기능

### 사용자 기능

| ID | 기능 | 설명 |
|---|---|---|
| F-01 | 회차 선택 | 콘텐츠가 존재하는 회차만 목록에 노출 |

| F-03 | 문항 목록 표시 | 선택된 교시의 변형문제를 순서대로 표시. 답 미노출 |
| F-04 | 오마주 출처 표기 | 각 문항이 어느 기출을 변형한 것인지 식별 정보 표시 |
| F-05 | 해설 열람 | 문항별 버튼으로 해설 표시·숨김 |
| F-06 | 도면 표시 | 해설 내 도면 이미지 표시 및 확대 |

### 운영 기능

| ID | 기능 | 설명 |
|---|---|---|
| F-07 | 콘텐츠 등록 | 문항·해설·도면을 서비스에 반영하는 수단 |
| F-08 | 공개 제어 | 검수 미완료 콘텐츠의 노출 차단 |

F-07이 없으면 회차를 하나 추가할 때마다 코드 수정과 재배포가 필요하다. 콘텐츠가 계속 늘어나는 서비스이므로 1차 범위에 포함한다.

## 5. 요구사항

우선순위 — M 1차 배포 필수 · S 가능하면 포함 · C 2차 이후
프로토타입 — ○ 반영 · △ 부분 · ✗ 구현 단계 대상

### 5-1. 화면·조회

| ID | 요구사항 | 우선 | 프로토타입 |
|---|---|---|---|
| R-01 | 회차 드롭다운에는 공개 상태 콘텐츠가 1건 이상 있는 회차만 노출한다 | M | ○ |
| R-02 | 교시 드롭다운은 선택된 회차에 따라 목록이 바뀐다 | M | △ |
| R-03 | 콘텐츠가 없는 교시는 선택할 수 없어야 한다 | M | ○ |
| R-04 | 문항 목록은 문항 번호 순으로 표시한다 | M | ○ |
| R-05 | 문항 목록 화면에는 답·해설이 어떤 형태로도 포함되지 않는다 | M | ○ |
| R-06 | 각 문항에 오마주 원 기출의 식별 정보를 표시한다 | M | ○ |
| R-07 | 오마주 표기는 출처 식별까지만 하고 기출 원문은 게재하지 않는다 | M | ○ |

R-02는 현재 회차가 139회 하나뿐이라 연동 동작을 확인할 수 없다. 교시 목록은 고정 상태다.

### 5-2. 해설

| ID | 요구사항 | 우선 | 프로토타입 |
|---|---|---|---|
| R-08 | 해설은 문항별로 개별 열람·닫기가 가능하다 | M | ○ |
| R-09 | 해설 데이터는 열람 요청 시점에 서버에서 받아온다 | M | ✗ |
| R-10 | 해설에는 모범답안 본문과 해당 도면이 함께 표시된다 | M | ○ |
| R-11 | 도면은 원본 비율을 유지하며 확대해서 볼 수 있어야 한다 | M | ○ |
| R-12 | 도면이 없는 문항은 본문만 표시하고 빈 영역을 남기지 않는다 | S | ○ |

**R-09이 핵심이다.** 해설을 화면에 미리 실어두고 버튼으로 숨기기만 하면 브라우저 소스보기로 전부 노출된다. 답을 감추는 것이 이 서비스의 성립 조건이므로 화면 설계가 아니라 요구사항으로 못 박는다.

정적 프로토타입에는 서버가 없으므로 해설 데이터가 `index.html`에 함께 들어 있다. 구현 단계에서 해설을 별도 엔드포인트로 분리해야 한다.

### 5-3. 콘텐츠 운영

| ID | 요구사항 | 우선 | 프로토타입 |
|---|---|---|---|
| R-13 | 문항·해설 추가 시 코드 수정과 재배포 없이 반영할 수 있어야 한다 | M | △ |
| R-14 | 콘텐츠는 문항 단위로 공개·비공개 상태를 가진다 | M | ✗ |
| R-15 | 비공개 콘텐츠는 목록·해설 어디에도 노출되지 않는다 | M | ✗ |
| R-16 | 도면 파일은 등록 시점의 원본이 변형 없이 보존되어야 한다 | M | ○ |
| R-17 | 콘텐츠 등록 수단은 관리자만 접근할 수 있다 | M | ✗ |

R-13은 데이터에서 화면을 생성하는 구조까지만 갖췄다. 재배포는 여전히 필요하다.

**R-16의 배경** — 도면 11건은 SHA-256 해시로 잠겨 있고 승인 이후 수정 금지 상태다. 서비스가 이미지를 재인코딩하거나 리사이즈하면 이 무결성이 깨진다. 이 리포의 `drawings/` 는 원본 바이트 그대로이며 빌드 시 해시를 검증한다.

### 5-4. 비기능

| ID | 요구사항 | 우선 | 프로토타입 |
|---|---|---|---|
| R-18 | PC와 모바일 브라우저 모두에서 정상 표시된다 | M | ○ |
| R-19 | 도면 확대 시 텍스트와 수치가 판독 가능해야 한다 | M | ○ |

## 6-2. 과목 분류

원본 문항 데이터에는 과목 필드가 없다. 기획 초안 v3의 `CATEGORY`에 대응하기 위해 별도 매핑을 두었다.

| 문항 | 제목 | 과목 |
|---|---|---|
| 1 | 곡선교 받침 — 공용 중 손상의 원인 진단과 개선 배치 | 교량공학 |
| 2 | a/d에 따른 파괴모드 — 실무 부재의 설계법 판단 | 콘크리트구조 |
| 3 | 설계 VE — 교량 설계 시나리오 적용과 한계 | 건설관리 |
| 4 | 프랫 트러스 사재 영향선과 이동하중 최대 부재력 | 구조역학 |
| 5 | 중앙 탄성지지 단순보 — 강성 분담과 역산 | 구조역학 |
| 6 | PSC 합성거더 — 두 조건을 만족하는 긴장력 범위 | 콘크리트구조 |

**이 분류는 검수를 거친 데이터가 아니다.** 해시로 잠긴 문항 JSON을 수정하지 않기 위해 `data/categories.json`에 분리해 두었고, 분류를 바꿀 때는 이 파일과 `tools/build.py`의 `CATEGORIES`만 고치면 된다.

2번(전단·STM)과 6번(PSC)은 세분하면 다른 과목이나 "과목 단위" 기준에 따라 콘크리트구조로 묶었다. 1번은 받침 손상 진단이지만 곡선교의 구조적 거동을 묻는 문제여서 교량공학으로 두었다. 3번 VE는 구조 과목이 아니어서 건설관리로 분리했다.

### 년도 표기

기획 초안 v3의 `EXAM{year, round}` 중 `year`는 원본 데이터에 없다. 년도 표기를 생략하고 회차·교시만 사용한다.

## 7. 데이터 취급 규칙

원본 문항 데이터는 공개 필드와 내부 필드로 나뉜다.

| 구분 | 필드 | 화면 |
|---|---|---|
| 공개 | `question` `model_answer` `drawings` `homage` | 노출 |
| 선택 | `title` `type` `difficulty_stars` | 노출 |
| 내부 | `origin` `learning_objective` `variation_design` `drawing_requirements` `self_review` `reference` | **비노출** |

내부 필드는 제작·검수용 자료다. 특히 `reference`는 설계기준 조항번호가 미확정 상태이므로 공개해서는 안 된다.

**이 리포에는 원본 데이터 패키지를 포함하지 않는다.** `data/139-3.public.json`은 공개 필드만 추출한 파일이며, 내부 필드가 담긴 원본은 `.gitignore`로 제외된다. 리포가 공개 상태라면 원본을 커밋하는 순간 내부 자료가 그대로 공개된다.

---

## 8. 재빌드

원본 데이터 패키지(`139-3-content-data.zip` 해제본)를 `source/` 에 두고 실행한다.

```bash
python3 tools/build.py
```

스크립트가 하는 일:

1. 공개 필드만 읽어 `index.html` 생성 — 내부 필드는 읽지 않는다
2. 도면 원본을 `drawings/` 로 복사하고 SHA-256을 매니페스트와 대조
3. 공개 필드만 담은 `data/139-3.public.json` 출력
4. 생성된 HTML에 내부 필드 문자열이 섞이지 않았는지 검사 후 결과 출력

검사 결과가 `leaks: none`이 아니면 배포하지 않는다.

## 9. 알려진 제약

- 계산형 3문항(문항 4·5·6)은 원본 데이터에 `model_answer`가 없어 해설 버튼이 비활성 상태다. 답안 도면은 승인 완료본이 존재하나, R-10(본문+도면 동시 표시)을 충족하지 못해 노출하지 않는다.
- 문제 도면을 문항 목록 화면에 표시한다. 정의서 2-2 화면 구성표에는 목록에 도면이 없으나, 문항 4·6이 도면을 전제로 서술되어 있어 도면 없이는 문제가 성립하지 않는다. 정의서 개정 대상이다.
- 회차·교시 드롭다운의 선택지가 하드코딩되어 있다. 콘텐츠가 늘면 데이터에서 생성하도록 바꿔야 한다.
- 과목 분류는 검수 전이다. 특히 문항 1(교량공학)과 문항 3(건설관리)은 이견 여지가 있다.
- 과목별로 들어가면 구조역학 2문항은 해설이 모두 준비 중이라 열람 가능한 해설이 0건이다. 과목 목록에 해설 보유 수를 함께 노출할지는 미정.
- 랜덤 연습의 문항 풀이 6건뿐이라 무작위의 의미가 약하다. `count` 파라미터(API 스케치 8절)는 적용하지 않고 전체를 섞는다.
- 기획 초안 v3의 REQ-U01은 "정답 기본 접힘(전개형)"으로 되어 있으나, 정의서 v0.1 R-09는 열람 시점 서버 조회를 요구한다. 클라이언트에서 접기만 하면 소스보기로 답이 노출되므로 구현 단계에서 R-09 기준을 따라야 한다.
- 관리자 화면에 인증이 없다. 공개 리포로 배포하면 URL을 아는 누구나 열 수 있다. 실제 데이터를 바꾸지는 못하지만(저장 없음), 구현 단계에서는 NFR-04대로 Spring Security 인증이 실제 방어선이어야 한다.
- 신고·추가풀이 목록은 예시 데이터다. 문항 제목만 실제와 맞추었고 신고 내용·작성자명은 만들어 넣은 것이다.
- v3의 데이터 모델에는 오마주 출처를 담을 필드가 없다. 현재 화면은 v0.1 기준(변형문제 + 출처 표기, 원문 미게재)을 유지하고 있다. 콘텐츠 성격이 확정되면 데이터 모델 정합을 다시 봐야 한다.
